# IMovies deployment guide

This guide deploys the existing client to Vercel, the Express API to Render, and stores application data in MongoDB Atlas. It does not contain project-specific production URLs; use the service URLs generated by your own accounts.

## 1. Prepare MongoDB Atlas

1. Select the Atlas cluster and create or select an application database user with only the permissions the application needs.
2. In **Network Access**, allow the Render service to reach the cluster. Use Render’s documented outbound IP ranges or a static outbound IP option if enabled for your plan. Avoid opening access to every IP for a production database.
3. Copy the Node.js connection URI. Do not put it in GitHub, this document, or a `VITE_` frontend variable. Add it to Render as `MONGODB_URI` in the next step.

## 2. Deploy the API to Render

1. Push the project to a GitHub repository yourself, then create a Render **Web Service** from that repository.
2. Set **Root Directory** to `server`.
3. Set the runtime to Node. Use:
   - Build command: `npm ci`
   - Start command: `npm start`
4. Configure these environment variables in Render’s service settings:

   | Name | Value |
   | --- | --- |
   | `NODE_ENV` | `production` |
   | `MONGODB_URI` | Your private Atlas connection URI |
   | `JWT_SECRET` | A newly generated random secret of at least 32 characters |
   | `CLIENT_URL` | Exact frontend origin displayed by Vercel, without a trailing slash |
   | `DNS_SERVERS` | `1.1.1.1,8.8.8.8` (optional; set this if the host’s default resolver cannot resolve Atlas SRV records) |
   | `JWT_EXPIRES_IN` | Optional; defaults to `7d` |

   Render supplies `PORT`; do not hardcode it. Admin seed credentials are not required by the running API and should not be configured on the production service.
5. The service health check path is `/api/health`, as configured in `render.yaml`. This is an API liveness check; successful database connection is confirmed separately in the service startup logs.
6. Wait for the service to start. Confirm its logs say the API connected to MongoDB before proceeding. Do not run the development seed on production as a deployment step.

The root `render.yaml` describes a Render web service and leaves secret values unsynchronized. Review the resulting environment values in Render before publishing.

## 3. Deploy the frontend to Vercel

1. Import the same GitHub repository as a Vercel project.
2. Set **Root Directory** to `client` and use the Vite framework preset.
3. Use:
   - Install command: `npm ci`
   - Build command: `npm run build`
   - Output directory: `dist`
4. Set the build environment variable `VITE_API_URL` to the Render service origin displayed in its dashboard, followed by `/api`.
5. Deploy and copy the exact Vercel site origin. The client’s `vercel.json` rewrite routes deep links back to the SPA entry point.

## 4. Connect the two deployed services

1. Set Render’s `CLIENT_URL` to the exact Vercel origin, without a trailing slash. For multiple trusted frontend origins, use a comma-separated list.
2. Redeploy the Render API after changing `CLIENT_URL`.
3. In Atlas Network Access, confirm that the Render API can reach the cluster. A successful connection from a developer laptop does not automatically grant Atlas access to Render.
4. Test `/api/health`, movie listing, showtimes, authentication, and a controlled booking in the deployed app. Check the Render and Vercel logs for errors; never include secrets in diagnostic output.

## Environment variable inventory

### Render API

- Required: `MONGODB_URI`, `JWT_SECRET`, `CLIENT_URL`.
- Set by Render: `PORT`.
- Recommended: `NODE_ENV=production`.
- Optional: `DNS_SERVERS`, `JWT_EXPIRES_IN`.
- Seed-only local values: `ADMIN_NAME`, `ADMIN_EMAIL`, `ADMIN_PASSWORD`. Do not run the development seed in production.

### Vercel frontend

- Required for deployment: `VITE_API_URL`, set to the Render API base URL ending in `/api`.
- Never place secrets in frontend environment variables. Every `VITE_` variable is bundled into public client code.

## Local pre-deployment checks

From the repository root:

```sh
npm test
npm run test:client
npm run lint
npm run build
```

Deployments and account configuration remain manual. This repository contains no real deployment URLs or credentials.
